# Предусмотренные баги и их обработка

Реестр того, что ломается в утилитах «голос в любое поле», и как SpokenGo это
закрывает. Каждый пункт привязан к месту в коде и к тесту.

## A. Фокус и вставка не туда

1. **Наш оверлей/трей крадёт фокус — текст уходит в нашу форму.**
   Окно записи создаётся с `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`, трей не
   активируется. Цель вставки фиксируется в момент хоткея.
   → `inject/windows.py`, `pipeline.py`.

2. **Фокус сменился между записью и вставкой.**
   Запоминаем HWND цели на старте записи, перед вставкой делаем
   `SetForegroundWindow(target)`. → `inject/windows.py`.

3. **«Никуда не нажал» — нет активного поля.**
   Ведём историю смены foreground (WinEvent-хук). Если активна наша/системная
   оболочка, берём последнее прикладное окно. → `inject/windows.py:resolve_target`,
   тест `test_clipboard.py::test_target_resolution`.

4. **Целевое окно elevated, наш процесс — нет (UIPI блокирует SendInput).**
   Ловим неудачу вставки, уведомляем и предлагаем запуск от админа; текст уже в
   буфере. → `pipeline.py` фолбэк.

5. **Поле блокирует Ctrl+V (пароль/UWP/кастомный контрол).**
   Фолбэк на посимвольный `SendInput` с юникод-скан-кодами.
   → `inject/windows.py:type_text`.

## B. Гонки буфера обмена

6. **Вставка раньше, чем буфер записан.**
   После `set` ждём и проверяем, что в буфере наш текст, только потом Ctrl+V.
   → `inject/clipboard.py::ClipboardCycle`.

7. **Восстановили старый буфер раньше, чем вставка дочитала.**
   Restore только после подтверждённого Ctrl+V + задержка.
   → тест `test_clipboard.py::test_restores_after_paste`.

8. **Буфер занят другим процессом (`OpenClipboard` падает).**
   Ретраи с backoff. → `ClipboardCycle._with_retry`,
   тест `test_clipboard.py::test_retries_when_busy`.

9. **В буфере была картинка/файлы, а мы затёрли текстом.**
   Снимок всех важных форматов, восстановление как было.
   → `inject/windows.py:snapshot_clipboard`.

## C. Состояние и хоткей

10. **Автоповтор клавиши / двойной хук → двойной старт.**
    Дебаунс < 250 мс. → `state.py::StateMachine.on_hotkey`,
    тест `test_state.py::test_debounce`.

11. **Второй хоткей во время транскрипции/вставки.**
    Запрещённый переход автомата, тихо игнорируется.
    → тест `test_state.py::test_rejects_concurrent_start`.

12. **Зависание в не-IDLE при ошибке.**
    Любая ошибка → `ERROR → IDLE`. → тест `test_state.py::test_error_recovers`.

13. **`Ctrl+Space` занят (IME переключения языка и т.п.).**
    Хоткей настраиваемый; ловим провал `RegisterHotKey` и уведомляем.
    → `hotkeys.py`.

14. **Два инстанса приложения.**
    Single-instance через именованный мьютекс. → `app.py`.

## D. Аудио

15. **Нет микрофона / устройство занято.**
    Понятная ошибка, остаёмся в IDLE. → `audio.py`.

16. **Устройство отключилось во время записи.**
    Стоп + сохраняем уже записанное. → `audio.py`.

17. **Пустая запись / тишина.**
    RMS-порог: не шлём в API и не вставляем.
    → `audio.py:is_silent`, тест `test_audio.py::test_silence_detection`.

18. **Слишком длинная запись → превышение лимита размера API (Groq ~25–100 МБ).**
    Жёсткий лимит длительности + авто-стоп; при необходимости перекодирование.
    → `audio.py`, тест `test_audio.py::test_autostop_on_limit`.

## E. Сеть, API, секреты

19. **Нет сети / API недоступен.**
    Аудио в офлайн-очередь, ретрай фоновым воркером, уведомление.
    → `storage.py`, `pipeline.py`, тест `test_pipeline.py::test_queues_on_network_error`.

20. **Невалидный/просроченный ключ (401).**
    `AuthError` → уведомление + открыть настройки.
    → `transcribe/groq_provider.py`, тест `test_transcribe_groq.py::test_auth_error`.

21. **Rate limit (429).**
    Ретрай с экспоненциальной паузой. → тест `test_transcribe_groq.py::test_retry_then_success`.

22. **Файл больше лимита (413).**
    `FileTooLargeError` с подсказкой. → тест `test_transcribe_groq.py::test_file_too_large`.

23. **Ключ в plaintext (риск утечки в open-source).**
    Ключ в Credential Manager через keyring, не в конфиге/репозитории.
    → `secrets_store.py`, тест `test_config.py::test_secret_roundtrip`.

## F. Текст и локали

24. **Юникод/кириллица при фолбэк-наборе.**
    Юникод-скан-коды в `SendInput`, не виртуальные коды раскладки.
    → `inject/windows.py:type_text`.

25. **Whisper «галлюцинирует» на тишине/шуме (повторяющиеся фразы).**
    Детектор тишины до отправки + опциональная фильтрация коротких артефактов.
    → `audio.py`, `pipeline.py`.

## G. Приватность

26. **Пользователь не хочет хранить аудио.**
    Опция «не хранить аудио» и авто-удаление через N дней.
    → `config.py`, `storage.py`, тест `test_storage.py::test_autocleanup`.

## H. Продакшен-фиксы v0.2 (по фидбэку реального запуска)

27. **Лавина API-запросов при долгой записи (главный баг).**
    Авто-стоп по лимиту длительности срабатывал на КАЖДОМ аудио-блоке после
    превышения → десятки потоков транскрипции в секунду. Теперь авто-стоп
    одноразовый (`Event`-флаг в `AudioRecorder`), а остановка идёт через единый
    лок-защищённый `GuiController._finish_recording`, который переводит состояние
    ровно один раз и стартует ровно одну транскрипцию.
    → тесты `test_autostop.py`.

28. **«Распознаю» мигало / «в очереди» без причины.**
    Следствие #27: параллельные потоки + 429 от Groq уходили в очередь. Ушло
    вместе с #27. Состояние при авто-стопе теперь корректно RECORDING→TRANSCRIBING
    (`StateMachine.ensure_transcribing`).

29. **Неверная модель уходила в бесконечный ретрай.**
    400/404/422 от Groq теперь `BadRequestError` (permanent) — НЕ в очередь, а
    сразу понятное сообщение со списком валидных моделей. Ошибки разделены на
    permanent (ключ, модель, размер файла) и transient (429/5xx/сеть).
    → `transcribe/groq_provider.py`, тесты `test_transcribe_groq.py`.

30. **Скрытый фоновый расход API.**
    Авто-ретрай очереди выключен по умолчанию (`auto_retry=false`). Очередь
    повторяется только вручную («Повторить очередь») и ограничена 3 попытками,
    дальше — статус `failed`. → `pipeline.py`, тесты `test_pipeline.py`.

31. **Ключ API «пропадал» после сохранения.**
    Поле ключа маскированное и очищается после сохранения — выглядело как потеря.
    Теперь есть индикатор «● ключ API задан», пустое поле = оставить текущий ключ
    (не перезатираем). → `ui_tk.py`, `controller.save_settings`.

32. **Выбор модели вслепую.**
    Модель теперь выпадающий список валидных Groq-моделей, а не свободный ввод.
    Лимит длительности снижен со 120 до 60 с (≈1.9 МБ, заведомо < 25 МБ).

## I. Оверлей записи и сосуществование с другими приложениями (v0.3)

33. **Маленькое окно-индикатор не должно красть фокус.**
    Оверлей записи — borderless topmost Toplevel с `WS_EX_NOACTIVATE |
    WS_EX_TOOLWINDOW`. Иначе вставка ушла бы в него. Все его методы
    маршалятся на Tk-поток (можно звать из аудио/воркер-потоков).
    → `overlay.py:TkOverlay`.

34. **Видно, КУДА вставится текст.**
    В оверлее — иконка и имя приложения, которое было в фокусе на момент
    хоткея (та же цель, что и для вставки). Иконка берётся из окна
    (`WM_GETICON`/класс) с фолбэком из .exe; нет иконки → буква-аватар.
    → `inject/win_icon.py`, `overlay.py`, тесты `test_overlay.py`.

35. **Конфликт с записью голоса в других приложениях.**
    Микрофон открывается в shared-режиме (WASAPI по умолчанию) и только на
    время диктовки, сразу закрывается — мы сосуществуем с Telegram/Zoom/Discord
    и не держим устройство. Если мик занят эксклюзивно — понятное сообщение,
    приложение остаётся в IDLE. → `audio.py`.

36. **Оверлей всегда убирается.**
    `hide()` вызывается на всех терминальных путях (успех, тишина, ошибка
    провайдера, сбой записи) через `_emit_idle`. → тесты `test_overlay.py`.

## J. Хоткеи, единственный экземпляр, ключ (v0.4)

37. **Два экземпляра дрались за Ctrl+Space → краш «комбинация занята».**
    Установщик клал в автозагрузку фоновый `run`, а ручной `gui` пытался занять
    тот же хоткей. Теперь: single-instance мьютекс (`single_instance.py`),
    автозагрузка запускает `gui`, второй запуск просто выходит.

38. **Падение потока хоткея при занятой комбинации.**
    `RegisterHotKey` раньше кидал исключение прямо в потоке (видимый traceback).
    Теперь хоткей-поток с message-loop, ошибка регистрации идёт в колбэк
    `on_error` → сообщение в окне, приложение живёт. → `hotkeys.py`.

39. **Стоп записи ненадёжен по тому же хоткею.**
    Старт — настраиваемое сочетание, **стоп — Enter, отмена — Esc**. Enter/Esc
    регистрируются динамически только на время записи (не перехватывают Enter
    в системе вне записи). → `controller.start/stop/cancel_recording`,
    `app.py`, `ui_tk.py`, тесты `test_recording_controls.py`.

40. **Сочетание задаётся нажатием клавиш.**
    Кнопка «Задать клавишей» ловит следующее сочетание (Ctrl/Alt/Shift + клавиша)
    через события Tk; `combo_from_state` собирает строку.
    → тесты `test_hotkeys.py`.

41. **Непонятное состояние ключа + «ключ уже задан».**
    Ключ хранится в Credential Manager (переживает перезапуск и переустановку —
    отсюда «уже задан» на чистом старте). Теперь видно «● задан gsk_…1234» с
    маскированной подсказкой, пустое поле = не менять, есть кнопка «Очистить».
    Настройки упрощены: ключ, сочетание, модель. → `controller`, `ui_tk.py`,
    тесты `test_keymgmt.py`.

42. **Ctrl+V не вставлял ключ при русской раскладке.**
    Tkinter по умолчанию вешает вставку на символ «v», который не приходит при
    кириллической раскладке (там это «м»). Теперь Ctrl+C/V/X/A ловятся по
    keycode (раскладко-независимо), плюс правый клик → «Вставить» на поле ключа.
    → `hotkeys.clipboard_action`, `ui_tk._enable_clipboard`, тесты `test_hotkeys.py`.

## K. Диагностика (v0.5)

43. **Непонятные «ошибки распознавания» без деталей.**
    Добавлен файловый лог `%APPDATA%/SpokenGo/spokengo.log` (с ротацией): пишутся
    все статусы, точный ответ Groq при ошибке и трейсбеки исключений. Смотреть:
    `spokengo logs` (или `-n 200`). → `logging_setup.py`, `controller`, `pipeline`,
    тесты `test_logging.py`.

44. **Оверлей «застывает» на первом приложении — это by design.**
    Цель вставки фиксируется в момент хоткея; оверлей намеренно показывает её и
    не меняется при переключении окон, иначе текст ушёл бы не туда.

## L. Сетевой блок и гонка вставки при смене окна (v0.5.x)

45. **403 от Cloudflare (error 1010) на каждый запрос.**
    Дефолтный `User-Agent: Python-urllib` блокировался Cloudflare перед Groq.
    Добавлен нормальный `User-Agent`/`Accept`. 403 теперь — постоянная ошибка с
    подсказкой про Cloudflare/VPN. → `transcribe/groq_provider.py`,
    тесты `test_transcribe_groq.py`.

46. **Вставлялся старый буфер вместо транскрипта при смене окна.**
    После переключения окна возврат фокуса через `SetForegroundWindow` добавляет
    задержку, а мы восстанавливали буфер слишком рано — приложение успевало
    вставить старое содержимое. Теперь: восстановление буфера через `restore_delay`
    (0.5 с) после Ctrl+V, и надёжный возврат фокуса (`AttachThreadInput` +
    ожидание, что окно реально стало активным). → `inject/clipboard.py`,
    `inject/windows.py`, тест `test_clipboard.py::test_restore_waits_for_consume_delay`.

## M. Цель вставки = текущее окно + оформление оверлея (v0.6)

47. **Цель вставки берётся в момент СТОПА (текущее активное окно).**
    Windows ненадёжно отдаёт фокус обратно стартовому окну, поэтому теперь текст
    идёт туда, где пользователь сейчас, — предсказуемо, без борьбы за фокус.
    → `controller._finish_recording`, тест `test_stop_target.py`.

48. **Оверлей в реальном времени показывает, КУДА уйдёт текст.**
    Во время записи мини-окно опрашивает текущее активное приложение
    (`peek_target`) и обновляет иконку/имя, совпадая с целью на стопе.
    → `overlay.TkOverlay._poll`, `ui_tk`.

49. **Оформление окна записи.** Скруглённые углы (`SetWindowRgn`), без «.exe»
    (`display_name`), без стрелки, лёгкий переливчатый градиент (анимация hue на
    Canvas). → `overlay.py`, тест `test_overlay.py::test_display_name_*`.

## N. Переделка оверлея: Pillow + layered-окно (v0.6.1)

50. **Оверлей выглядел как «загрузка», с чёрными углами и белой полосой.**
    Причина: Tkinter Canvas не умеет сглаженные скругления, плавный градиент и
    альфу — «градиент» подделывался полосками (вид загрузки), обрезка окна давала
    чёрные углы. Решение: вся плашка рисуется в Pillow (AA-скругление, плавный
    градиент, мягкая тень) и показывается через Windows layered-окно с попиксельной
    альфой (`UpdateLayeredWindow`). Статичная, без анимации и пульсации, заметно
    уже. → `overlay.render_pill`, `overlay.TkOverlay._paint`.

## O. Alt-фикс, анимация оверлея, тёмная тема (v0.7)

51. **К любому сочетанию прилипал «alt».**
    Бит `0x0008` ошибочно считался Alt; на Windows Alt — это `0x20000`. Убрал
    лишний бит. → `hotkeys.combo_from_state`, тест `test_hotkeys.py`.

52. **Вернул анимацию в оверлей — «сонар-пинг».**
    Вместо резкой пульсации — расходящиеся кольца вокруг точки + лёгкое «дыхание»
    ядра (Pillow-кадры, ~18 fps, layered-окно). Живое обновление целевого окна
    сохранено; добавлена серая подсказка «Enter — отправить · Esc — отмена».
    → `overlay.render_base/frame_image`, тесты `test_overlay.py`.

53. **Тёмная тема главного окна.**
    Полностью тёмная палитра (в тон плашке), карточки настроек, кастомные вкладки,
    «геройная» кнопка записи со скруглением (Pillow), статус-чип, тёмные поля/
    список. → `ui_tk.py`.

## P. UX-правки настроек + надёжность оверлея (v0.7.1)

54. **Оверлей мог не появляться (после перехода на анимацию).**
    Отрисовка была отложена в цикл анимации. Теперь плашка рисуется сразу при
    показе (синхронно), а сбои логируются в `spokengo.log`.
    → `overlay.TkOverlay._paint_frame/_show`.

55. **Поле ключа выглядело пустым при «ключ задан».**
    Теперь поле префиллится сохранённым ключом под маской (звёздочки), не пустое.
    → `controller.stored_key`, `ui_tk._refresh_key_status`.

56. **Убрана кнопка «Сохранить настройки».**
    Модель и сочетание применяются сразу при выборе/назначении. Ключ — своя
    кнопка «Сохранить» + крестик «✕» очистки в одну строку с полем.
    → `ui_tk._select_model/_on_capture_key`.

57. **Уродливый выпадающий список модели с белой обводкой.**
    Заменён на сегмент-контрол из двух кнопок (Turbo / Large v3), применяется
    мгновенно. → `ui_tk._build_settings`.

## Q. Оверлей: мелькал один раз и исчезал (v0.7.2)

58. **Layered-окно гасло из-за Tk geometry.**
    На каждый кадр/смену цели звался `Tk .geometry()` + `update_idletasks()`,
    которые пере-маппят окно и стирают содержимое layered-слоя → плашка мелькала
    раз и пропадала. Теперь позиция/размер задаются ТОЛЬКО через
    `UpdateLayeredWindow` (pdst/size), Tk-геометрия не трогается; окно скрыто до
    первого кадра (`withdraw`). → `overlay.TkOverlay._rebuild_base/_ensure`.


## R. Оверлей снова держится (v0.7.3)

59. **Анимация рисовала кадры БЕЗ Tk geometry — окно теряло размер и гасло.**
    Рабочая статичная версия (v0.6) задавала `geometry()` ВМЕСТЕ с каждой
    отрисовкой. Цикл анимации красил только `UpdateLayeredWindow` без geometry,
    и после ближайшего idle-события Tk окно сворачивалось до дефолтного размера,
    обрезая layered-картинку в ноль → «мелькнуло раз и пропало». Теперь geometry
    задаётся в КАЖДОМ кадре (как в v0.6), анимация замедлена (~11 fps), `withdraw`
    убран, рендер защищён от падений, show/hide логируются.
    → `overlay.TkOverlay._paint_frame`.


## S. Оверлей: нативное layered-окно вместо Tk (v0.7.4)

60. **Мерцание плашки.** Две причины: (1) ctypes-хэндлы GDI (HDC/HBITMAP —
    указатели) не имели заданных типов → на 64-бит обрезались до 32 бит → хэндлы
    то валидные, то нет → мерцание; (2) Tk-окно перерисовывало себя, и удержание
    размера через `geometry()` на каждый кадр само мерцало. Решение: оверлей
    теперь — настоящее НАТИВНОЕ layered-окно (pywin32 `CreateWindowEx` +
    `UpdateLayeredWindow`), без Tk-Toplevel; заданы корректные ctypes-типы для
    всех хэндлов. Tk остаётся только таймером анимации (его mainloop сам
    прокачивает сообщения нативного окна, т.к. оно создано в том же потоке).
    → `overlay._LayeredWin`, `overlay.TkOverlay`.
