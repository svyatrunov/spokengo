# SpokenGo — план реализации

Голосовой ввод в любое поле по глобальному хоткею. Нажал `Ctrl+Space` в любом
месте → пишется аудио → транскрибируется (Groq Whisper) → текст мгновенно
вставляется в то поле, которое было в фокусе. Аудио и транскрипты сохраняются
локально для восстановления. Open-source, на старте работает на одном API-ключе
Groq, но провайдеры подключаемые.

Целевая платформа MVP: **Windows**. Стек: **Python**. Вставка: **буфер обмена +
Ctrl+V** (с фолбэком на посимвольный набор для полей, где вставка заблокирована).

---

## 0. Принципы, на которых держится дизайн

1. **Состояние — это конечный автомат.** Один источник правды о том, что сейчас
   происходит (idle / recording / transcribing / injecting / error). Любой баг
   «записал дважды», «вставил в момент записи», «завис» — это незаконный
   переход. Запрещаем переходы, а не латаем последствия.
2. **Фокус фиксируется в момент хоткея, а не в момент вставки.** Между записью и
   вставкой проходят секунды, окно фокуса может смениться. Цель вставки —
   окно/контрол, который был активен, когда пользователь нажал хоткей.
3. **Наш UI не должен красть фокус.** Оверлей записи — окно без активации
   (`WS_EX_NOACTIVATE`), трей не активируется. Иначе текст уедет в нашу же форму.
4. **Платформенный код изолирован за интерфейсами.** Вся логика (автомат, цикл
   буфера, очередь, провайдеры, хранилище) тестируется без Windows и без сети.
   Win32 и устройство микрофона подменяются моками.
5. **Деградация вместо падения.** Нет сети → ставим аудио в очередь. Вставка не
   прошла → копируем в буфер и уведомляем. Ключа нет → открываем настройки.
   Пользователь никогда не теряет надиктованное.

## Этап 1. Каркас, конфиг, секреты

**Что делаем.** Пакет `spokengo`, `pyproject.toml`, точка входа `__main__`.
Конфиг в TOML (`%APPDATA%/SpokenGo/config.toml`): хоткей, режим (toggle/
push-to-talk), провайдер, модель, язык, sample rate, макс. длительность, хранить
ли аудио, авто-удаление через N дней. API-ключ **не в конфиге** — в Windows
Credential Manager через `keyring` (фолбэк — зашифрованный файл).

**Почему так.** Ключ в plaintext в репозитории/конфиге — классическая утечка для
open-source утилит. Разделяем «настройки» (можно коммитить пример) и «секреты».

**Тесты.** Загрузка дефолтов; мерж пользовательских значений поверх дефолтов;
сохранение/чтение round-trip; невалидный TOML → понятная ошибка, не краш;
secrets_store кладёт и достаёт ключ через мок keyring.

## Этап 2. Конечный автомат и анти-дребезг хоткея

**Что делаем.** `StateMachine` со состояниями `IDLE → RECORDING → TRANSCRIBING →
INJECTING → IDLE` и боковым `ERROR → IDLE`. Разрешённые переходы заданы таблицей,
незаконный переход кидает `InvalidTransition`. Дебаунс хоткея (игнорируем
повторные срабатывания < 250 мс — автоповтор клавиши и двойные хуки).

**Почему так.** 80% «странных» багов таких утилит — гонки состояний: второй
хоткей во время транскрипции, повторное срабатывание от key-repeat, вставка,
пока ещё идёт запись. Автомат превращает их в явные запрещённые переходы.

**Тесты.** Полный happy-path цикл; повторный старт во время записи отклонён;
дебаунс режет быстрый повтор; из ERROR всегда можно вернуться в IDLE; toggle vs
push-to-talk дают разные триггеры стоп-записи.

## Этап 3. Захват аудио

**Что делаем.** `AudioRecorder` на `sounddevice`: 16 кГц, моно, int16 (формат
Whisper). Пишем в кольцевой буфер в памяти, по стопу — в WAV во временный файл +
в локальное хранилище. Логику записи WAV (`write_wav(frames, sr, path)`) и
накопление буфера выделяем в чистые функции — они тестируются без устройства.
Жёсткий лимит длительности (по умолчанию 120 с) → авто-стоп, чтобы не упереться в
лимит размера API.

**Баги-митигации.** Микрофон занят/нет устройства → понятная ошибка + остаёмся в
IDLE. Устройство отключилось в процессе → стоп + сохранение уже записанного.
Тишина/пустая запись → не шлём в API, не вставляем.

**Тесты.** `write_wav` пишет валидный заголовок WAV (проверяем `wave` модулем);
накопитель склеивает чанки в нужном порядке; авто-стоп по лимиту; детектор тишины
по RMS-порогу.

---

## Этап 4. Провайдеры транскрипции (Groq на старте, расширяемо)

**Что делаем.** Интерфейс `TranscriptionProvider.transcribe(audio_path, *,
language) -> Transcript`. Реализация `GroqProvider` (эндпоинт
`audio/transcriptions`, модель `whisper-large-v3-turbo`). Реестр провайдеров
`registry.py` — добавить OpenAI/Deepgram/локальный whisper = один класс + одна
строка регистрации. Ретраи с экспоненциальной паузой на 429/5xx, таймаут,
понятные ошибки на 401 (ключ) и 413 (файл велик).

**Почему так.** Главная просьба — «требует ключи популярных моделей». Поэтому
провайдер — это плагин, а не хардкод. Контрибьютор добавляет провайдера, не
трогая ядро.

**Тесты** (HTTP замокан, без сети). Успех → `Transcript.text`; 401 → `AuthError`;
429 → ретрай и затем успех; 413 → `FileTooLargeError`; таймаут → `ProviderError`;
реестр отдаёт класс по имени и кидает понятную ошибку на неизвестное имя.

## Этап 5. Хранилище и офлайн-очередь

**Что делаем.** SQLite (`history.db`): таблица `transcripts` (id, ts, текст,
провайдер, модель, длительность, путь к аудио, статус). Файлы аудио рядом.
Очередь `pending` для записей, которые не удалось отправить (нет сети/ошибка) —
ретраятся фоновым воркером. Авто-очистка аудио старше N дней.

**Почему так.** Просьба «сохраняется в локальной памяти в случае чего». Это и
страховка от потери, и история, и фундамент офлайн-режима.

**Тесты.** Вставка и чтение записи; постановка в очередь и выборка pending;
пометка отправленной; авто-очистка удаляет старое и чистит файлы; БД создаётся,
если её нет.

## Этап 6. Захват/восстановление фокуса и вставка текста

**Что делаем (Windows).** В момент хоткея запоминаем `GetForegroundWindow()`
(HWND) и тред фокуса. Перед вставкой: `SetForegroundWindow(target)` →
сохраняем текущий буфер обмена (все важные форматы, минимум CF_UNICODETEXT) →
кладём транскрипт → шлём `Ctrl+V` через `SendInput` → ждём → восстанавливаем
буфер. Логику цикла буфера (`ClipboardCycle`: snapshot → set → paste-callback →
restore, с ретраями на «буфер занят») выносим в чистый класс поверх интерфейса
бэкенда буфера — она тестируется без Windows.

**«Если никуда не нажал — самое очевидное поле».** Если на момент хоткея активное
окно — наше собственное/рабочий стол/таскбар, берём последнее «настоящее»
прикладное окно из истории фокуса (ведём её через WinEvent-хук на смену
foreground). Внутри окна вставка идёт в контрол с фокусом клавиатуры; если его
нет, у большинства приложений Ctrl+V уходит в основное поле ввода.

**Фолбэк.** Если вставка не сработала (поле блокирует Ctrl+V, или это UWP/поле
пароля), переключаемся на посимвольный `SendInput` с юникод-скан-кодами.

**Баги-митигации.** Гонка буфера (вставка раньше, чем буфер записан) → задержка +
проверка содержимого перед Ctrl+V. Восстановление буфера раньше вставки → отдаём
Ctrl+V время завершиться, только потом restore. UIPI (наш процесс не elevated, а
целевое окно elevated) → честно сообщаем и предлагаем запустить от админа.
IME-конфликт `Ctrl+Space` → хоткей настраиваемый, ловим ошибку регистрации.
Не-текстовый буфер (картинка) → сохраняем и возвращаем как есть.

**Тесты.** `ClipboardCycle` восстанавливает прежний текст после вставки; ретрай
при «буфере занят»; пустой транскрипт не трогает буфер; выбор цели фокуса:
прикладное окно — берём его, наше окно — берём предыдущее из истории.

## Этап 7. Глобальный хоткей и оркестратор

**Что делаем.** `HotkeyManager` (Windows: `RegisterHotKey` в отдельном потоке с
message-loop; абстракция позволяет подменить на `pynput`). Оркестратор `app.py`
связывает хоткей → автомат → запись → (фоново) транскрипция → вставка, плюс трей
(`pystray`) с меню: статус, история, настройки, пауза, выход. Транскрипция и
сеть — в фоновом потоке, UI не блокируется.

**Баги-митигации.** Регистрация хоткея провалилась (занят) → уведомление и
подсказка сменить комбинацию. Двойной инстанс приложения → single-instance
через именованный мьютекс. Долгая транскрипция → индикатор в трее, не зависание.

**Тесты.** `VoicePipeline` со всеми зависимостями-моками гоняет полный сценарий:
старт→стоп→транскрипт→вставка→запись в историю; ошибка провайдера → аудио в
очередь + уведомление, состояние вернулось в IDLE; вставка упала → текст в
буфере + уведомление.

## Этап 8. Упаковка, дистрибуция, CI

**Что делаем.** `install.ps1` (создаёт venv, ставит пакет, кладёт ярлык в
автозагрузку), `build.ps1` (PyInstaller → один `.exe`). GitHub Actions: линт +
pytest на каждый PR, сборка артефакта на тег. README с быстрым стартом: получить
ключ Groq → вставить в настройках → готово.

**Тесты/проверки.** CI зелёный на Linux (ядро тестируется без Windows); сборка
exe проверяется на windows-раннере; smoke-запуск `--version`.
